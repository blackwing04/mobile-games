# 圖片 Brief 輸出格式（給 Gemini 用）

> **觸發**：當 user 說「我要跟 Gemini 討論畫 ChX 的插畫」/「幫我設計 ChX 的圖片設計稿」/ 類似請求時，啟動本格式。
>
> **輸出**：一份完整可貼進 Gemini 對話框當系統訊息的 MD（命名 `chXX_image_brief.md`）。
> user 把它整段貼到新開的 Gemini 對話 → Gemini 依此逐張產圖。

---

## ⚠️ 預設模式：直接動手，不要過度確認

user 對你的期待是「**讀完資料就把 brief 產出來**」，不是「先丟一堆問題問 user」。
你可以問問題，但**最多 2-3 個真正卡死的 canon-level 模糊點**。其他全部自己決策。

### 該自己決策的（**不要問 user**）

| 類別 | 為什麼不該問 |
|------|------------|
| 該章 canonical 已經寫過的視覺細節 | **直接讀文本提煉**。例：scene_lost_sanity 寫「臉像蠟一樣融化⋯露出底下平滑肉色皮膚」→ 你直接拿來當該結局 brief，不用問「假哥哥要用什麼母題」 |
| 跨章 NPC 救援時的造型 | canonical 通常已寫「跑著趕來、出汗、衣服亂」之類 → 直接抄。原造型參考前章 brief，加上「狼狽感」細節即可 |
| 該文化的常見場景物件 | Gemini 知道台式高中 / 老社區 / 公車站 / 警衛室長什麼樣。**不用幫 Gemini 寫 art direction 教學** |
| IP_BIBLE 已經規範的視覺通則 | 例：「夕陽橘 / 日光燈白」可不可以用 → IP_BIBLE 第 5 章已寫「場景圖**可以**有寫實光線」。你讀到就照辦，不用問 user |
| 變體場景要不要合併 / 拆分 | 你自己依「視覺差異是否顯著」判斷。例：door_stuck vs door_stuck_impatient 都在同教室同情境 → 共用 1 張；phone_again 4 變體場景完全不同（教室 / 桌底 / 走廊 / 樓梯）→ 各 1 張。**這是技術判斷，不是 user 拍板** |
| 標準的攝影 / 構圖選擇 | 主角用第二人稱 POV、背影、過肩 — 已是 IP 共識，不用每章重問 |

### 真的該問 user 的（**才開口**）

| 類別 | 範例 |
|------|------|
| 跨章節主角的「血脈視覺辨識」 | 例：Ch2 妹妹跟 Ch1 哥哥要不要五官 mirror（眉型 / 鼻型）— 這會影響 Ch3+ 設計，**值得 user 拍板** |
| canonical 沒提到的角色具體外觀 | 例：妹妹的制服款式（高中制服 vs 水手服 vs 運動服）— 跨章一致性鎖定，**1 個問題** |
| IP_BIBLE 未涵蓋的視覺新元素 | 例：Ch3 主角是駭客 → 他的工作環境視覺定調 user 沒提過 |
| 該章 wave 視覺技巧的分配 | 例：「Ch2 climax 用蠟臉 vs 黑霧空眼 vs 鏡中分身」三個都行 — 但只能挑一個當主視覺，**值得問** |

### 問問題的格式

如果真的要問，**最多 3 個**，寫成清楚的選項題（A/B/C），不要 open-ended。例：

> 兩個 Q 確認後我就產 brief：
>
> 1. 妹妹制服：(A) 白襯衫 + 深色百褶裙 + 馬尾（台式公立高中常見）/ (B) 水手服 / (C) 你心中已有具體想法請描述
> 2. 跟 Ch1 哥哥的五官 mirror：(A) 眉型 / (B) 鼻型 / (C) 都不刻意做（Gemini 自由發揮亞洲兄妹相似度）

別寫成 6 題的盤點報告。

### 還沒讀完 canonical 就別開口

99% 的 brief 設計疑問都能從 canonical narrative 提煉出來。**先讀完該章 canonical 的所有 narrative 段落 + ending description**，再決定要不要問。讀漏了問 user = 浪費雙方時間。

## ⛔ 禁止指定 Hex 色號 / 嚴格 palette 表

**這是最常被忽略但最嚴重的破壞 manhwa 畫風的錯誤**。

### 為什麼禁止

Gemini 看到 `#F0EDE5` / `#8B1A1A` / 嚴格 4 色 palette 表時會：
- 試圖**精確命中那幾個像素值**像 PS 套色
- 失去 manhwa 自然墨韻、灰階過渡、油墨暈染質感
- 結果「平面、扁、像數位填色」— 完全沒有韓系恐怖漫畫的手繪感

ch01_image_brief_example.md 雖然寫了 hex 碼，但 Ch1 出來的圖**靠的是 Sweet Home / Hellbound 風格參考的引導**，不是靠 hex 碼。Hex 碼是「給 user 看設計稿讀的規範」，**不該複製進 Gemini brief**。

### 該怎麼寫顏色描述

❌ **不要**寫：

```markdown
| 色 | Hex | 用途 |
|----|-----|------|
| 純黑 | `#000000` | 影子、頭髮 |
| 米白 | `#F0EDE5` | 高光、皮膚 |
| 冷灰 | `#6B7178` | 過渡灰階 |
| 血鏽紅 | `#8B1A1A` | 唯一彩色 |

**色塊處理**：地板用米白 + 血鏽紅暈染（取代橘色），妹妹米白襯衫 + 黑長髮純黑色塊
```

⭕ **要**寫：

```markdown
### 配色氛圍

整章維持**黑白基調**為主，**血鏽紅是唯一彩色**（用在血色夕陽、警示物、結局色調）。
所有「彩色」的存在用墨水暈染感（ink-wash bleeding）取代飽和色塊 — 這是韓系恐怖漫畫的色彩語言。

避免：飽和的紅綠藍黃紫粉、明亮活潑色彩、彩虹色、青色冷調。
```

每個 scene 的色彩描述也走「氛圍 + 描述詞」：

❌ **不要**：「米白磁磚地 + 冷灰課桌 + 純黑教室深處 + 妹妹米白襯衫 + 血鏽紅夕陽光浸染地板」

⭕ **要**：「黃昏血色光線斜灌進教室，地板被血色浸染如染血」

讓 Gemini 自己決定具體顏色強弱。它看 manhwa 風格參考會自己抓出對的色調。

### 描述顏色的詞庫

可以用：
- 「黑白基調」「黑白為主」「冷色調 ink-wash」
- 「血色」「血鏽色」「暗紅」「鏽紅」（描述紅的調性，不寫 hex）
- 「蒼白」「米白」「乳白」「象牙白」（描述米色家族）
- 「冷灰」「鉛灰」（描述中間調）
- 「墨黑」「純黑」「漆黑」（描述深暗）
- 「血色夕陽光」「日光燈白光」「螢幕冷光」（描述光源）

不要用：
- ❌ Hex 碼（`#XXXXXX`）
- ❌ RGB 值
- ❌ Pantone 色號
- ❌ 「精確 X 色塊」這種術語

### 統一風格的方式：靠風格參考，不靠色卡

讓 Gemini 對齊風格的有效手段：
- 「Korean manhwa horror style」+ 風格作品名（Sweet Home / Hellbound / Bastard）
- 「ink-wash bleeding」「flat black ink shapes」「limited palette」這類**質感描述詞**
- 「monochrome with one accent color」「rust-red as the only saturated hue」

**不是**色卡。色卡是給人類設計師對齊用的，Gemini 看了會誤解成像素級命令。

## ⚠️ 長度預算：硬上限 350 行

**Ch1 brief 439 行**已經是 Gemini 上下文承受極限。實測超過 ~500 行後 Gemini 會：
- 「同時滿足所有 constraint」→ 一張圖硬塞 5 個視覺破綻 → 邏輯崩
- 後段 scene brief 被前段風格規範淹沒 → 注意力分散
- 大段 🚨 英文指令被當成「全局必出元素」誤解

**目標：250–350 行整份**。超過就是失職。

### 行數分配建議

| 區塊 | 行數預算 |
|------|---------|
| 任務概述 + scene 清單 | ≤ 40 |
| 你是誰 + 專案背景 | ≤ 15 |
| 整體風格規範（4 色、線條、構圖） | ≤ 50 |
| 角色鎖定（主角 + NPC + 異象） | ≤ 50 |
| 技術規格 + 命名 + 禁止事項 | ≤ 25 |
| 工作流程 | ≤ 15 |
| **每個 scene brief** | **5–8 行** |
| 自我檢查清單 | ≤ 10 條 |

21 個 scene × 7 行 = 147 行。加上其他 ~200 行 = ~350 行。控住。

### 每個 scene brief 的精簡模板

```markdown
### N. `scene_xxx` ⭐（基準圖才加星）

**情境**：<1-2 句，最關鍵的視覺瞬間>
**構圖**：<3-5 個短句，鏡頭 / 主體 / 重點視覺破綻>
**情緒**：<2-3 個形容詞>
**人物**：<誰、姿勢、特殊細節>
```

**省略**：
- 「色塊處理」段（除非該 scene 有特殊配色，否則 system 段的 4 色 palette 已涵蓋）
- 重複出現的角色細節（例：「妹妹米白襯衫 + 黑長髮」每張都寫一遍 = 浪費）— 角色鎖定段已寫，scene 只標「妹妹」
- 「給 Gemini 的英文指令」🚨 區塊 — **只在 Gemini 真的會誤解時才加**（見下節）

### 🚨 英文補充指令的使用門檻

Ch1 用 🚨 英文指令在「沒有影子」上 — 因為 manhwa 沒有「不畫影子」這種反直覺處理，Gemini 不英文補充會自動畫一個。

**只在這幾種情況加 🚨**：
- 反直覺的 manhwa 處理（不畫某個元素）
- 中文易被 Gemini 誤譯（例：「肉色平滑面」→ 它可能畫成血紅色）
- 整章獨特的視覺 motif（每章最多 1-2 個，不是每個用到的 scene 都加）

**不該加 🚨 的情況**（Ch2 brief 的浪費）：
- ❌ 重複描述「滿頭大汗」「衣服亂」「手在抖」 — 中文已說清楚
- ❌ 描述標準 manhwa 構圖（雙重輪廓嘴型、影子延伸、空洞眼睛）— Gemini 看 Sweet Home 風格參考就會
- ❌ 強調「不要畫太多血」「克制描寫」— 在禁止事項段已涵蓋

每章 🚨 數量目標：**1–3 個**，不是 7-8 個。

### 共用視覺主題的處理

該章如果有「異象演化三型態」之類的母題（Ch2 假哥哥），**寫在角色鎖定段一次**（每型態 3-4 行），**scene brief 引用即可**：

❌ 浪費寫法（Ch2 brief）：
```
### scene_the_climax
... 假哥哥型態 1 詳述（雙重嘴型 / 影子怪 / 手錶 23:47 ...） ...
🚨 英文：The fake brother's mouth must be drawn with a double-outline...
```

⭕ 精簡寫法：
```
### scene_the_climax
**情境**：天台對峙，假哥哥背身轉過來。
**構圖**：寬鏡頭，前景排風管純黑剪影，中景假哥哥（型態 1，見角色段）半轉身，影子像爪子伸向妹妹腳邊。
**情緒**：偽裝的甜美 / 影子背叛了他
**人物**：假哥哥（型態 1）+ 妹妹遠景背影
```

差別 = 12 行 → 5 行。

| 輸入 | 用途 |
|------|------|

## 輸出 MD 必含章節（依此順序）

### 1. 任務概述 + 風格一致性 review
- 章節名 + 要產的圖數量
- 如果是「補圖」（Ch1 已 19 張，Ch2 是新的全部 16-20 張）— 區分清楚
- 提醒 Gemini「先打開 Ch1 已完成的 1-2 張對標風格再開始」（風格一致性是產圖最大失敗點）

### 2. 你是誰（給 Gemini 的角色設定）
- 「你是專業恐怖遊戲視覺概念設計師…」
- 心理恐怖 / 留白美學 / 東亞都市怪談 — 強調氛圍營造能力

### 3. 專案背景
- 遊戲類型 / 風格參考 / 設定（時代 + 文化背景）/ 市場 / 結局數量
- 直接抄 Ch1 brief 那段，**該章特殊背景才改寫**（例：Ch2 改成「校園 + 黃昏」）

### 4. 整體風格規範（**全章共用，直接抄 Ch1 brief**）
- manhwa horror style 關鍵詞
- 風格參照作品（Sweet Home / Hellbound / Bastard / Solo Leveling / All of Us Are Dead）
- 質感與線條（黑色塊陰影、粗細變化墨線、二元細節留白、無景深）
- **4 色 palette**（黑 / 米白 / 冷灰 / 血紅）— **不可改**
- manhwa 構圖思維（剪影、過肩、第二人稱 POV）

### 5. 角色鎖定（**該章主要角色清楚定義**）

每個重要角色寫：
- 年齡 / 性別 / 國籍
- 服裝（具體色塊 — 用 4 色 palette 描述）
- 髮型（黑色塊形狀）
- 異象啟動時的視覺特徵（沒有影子 / 空眼窩 / 黑霧 / 血痕等 — 沿用 Ch1 母題）
- 「正常時」vs「異象啟動時」差異

如果該章主角是前章主角的家人 / 朋友（Ch2 妹妹 = Ch1 哥哥），記得：
- 標出血脈關聯
- 髮色 / 五官有家族相似（為了視覺辨識）
- 但服裝 / 性格不同

NPC（救援者：上一章主角）：
- 「跑著趕來、出汗、衣服亂、書包帶子斷」這類「真實人感」要寫進 brief
- 對比幻覺中的乾淨無聲假人

### 6. 技術規格（直接抄 Ch1 brief，**不可改**）
- 16:9 橫向、1920×1080 或 1280×720
- WebP 優先，PNG 接受
- ≤ 200KB
- 不可包含文字 / 字幕 / logo / 浮水印 / AI 簽名

### 7. 命名規則（直接抄）
- 用 scene_id 命名：`scene_xxx.webp`
- 結局圖也是用 scene id 命名

### 8. 禁止事項表（直接抄 Ch1 brief，**全章都禁**）
- 照片寫實 / 3D
- 日系大眼睛 / chibi
- 配色超出 4 色
- 景深模糊
- 過度血腥
- 西方建築 / 西方人
- 白衣長髮女鬼老套造型
- 怪物完整正面
- 賽博龐克 / 蒸汽龐克
- 明亮飽和配色
- 任何文字

### 9. 工作流程
- 第一張先做 scene_start（風格基準）
- user 確認再進下一張
- 每張自我檢查清單

### 10. 該章特殊視覺 signature
**這是該章獨特的部分**。要點：
- 主視覺母題（Ch1 = 茶水間 + 電梯 + 日光燈白 / Ch2 = 教室 + 走廊 + 掛鐘 23:47 / Ch3+ = 待你設計）
- 色溫氛圍（Ch1 = 夜 + 冷白 / Ch2 = 黃昏 + 夕陽橘紅 — 但仍只用 4 色 palette 表達，「橘紅」用米白 + 血紅組合暗示，不額外加色）
- 與既有章節對比（Ch3 vs Ch1/Ch2 怎麼區隔，避免風格重複）

### 11. 場景 Brief 列表（最大區塊）

**每個要產的 scene 一筆**，依下列格式：

```markdown
### N. `scene_xxx` ⭐（如果是基準圖加星）
**情境**：<2-3 句話描述場景內發生什麼，從 canonical 的 narrative 提煉>
**構圖**：<鏡頭視角 / 主體位置 / 重點視覺元素 — 寫實具體，不抽象>
**色塊處理**：<黑塊在哪、米白光區在哪、血紅唯一彩色在哪 — 4 色怎麼分配>
**情緒**：<2-4 個形容詞>
**人物**：<該場景出現誰，姿勢 / 角度>

（如果有特殊 manhwa 處理技巧，例如 Ch1 「沒有影子」需要對 Gemini 特別說明，加一個 🚨 區塊強調）
```

#### 該寫哪些 scene
- 全部「玩家會看到」的 scene（即非 router 場景）
- 主場景 + 結局場景
- 變體家族家族（phone_again 主版 + 變體）— **建議每個變體都有自己的圖**（場景不一樣）；如果變體間視覺差別很小（例：door_stuck vs door_stuck_impatient 都在同教室），可以共用一張，brief 寫清楚共用情況
- router 場景**不畫**（玩家看不到）

#### 順序
- 通常照 canonical MD 的 scene 順序
- 主路線優先 → 分支 → 結局

## 風格特例：該章獨特技巧

如果該章有 Ch1「沒有影子」這種需要特殊 manhwa 處理的視覺技巧，要在對應 scene 的 brief 後加 🚨 強調區塊，**直接寫給 Gemini 的英文指示**。範例（Ch1）：

```markdown
**🚨 manhwa 處理「沒有影子」的關鍵指令給 Gemini：**
> 「In manhwa visual language, a shadow is just a black ink shape on the floor next to objects. For Xiao Ting specifically, simply do not draw any black shape under or next to her feet — the floor remains clean white where her shadow should be. ...」
```

英文是因為 Gemini 對英文視覺指令理解更精確（特別是 limited palette、ink wash bleeding、no depth blur 之類的詞）。

## 完成判準

你的 image brief MD 算「準備好交付」必須：

1. ✅ user 整段複製貼進 Gemini 對話框就能開工，**不用補充任何資訊**
2. ✅ 每個 scene 都有完整 4 段（情境/構圖/色塊/情緒/人物）
3. ✅ 4 色 palette 嚴格守住（沒寫 RGB 色 / 沒寫淺藍紫綠等）
4. ✅ 跟 Ch1 image_brief_example.md 結構一致（user 看了不會困惑）
5. ✅ 該章特殊視覺技巧（如果有）有專門的英文指示給 Gemini

---

## 不要做這些

- ❌ **不要寫 prompt 工程的咒語**（「8K, ultra detailed, masterpiece, best quality...」）— 那是 SD 用法，Gemini 不吃這套
- ❌ **不要在 brief 裡寫長篇 narrative**（會讓 Gemini 試圖「畫故事」而不是「畫單格」） — 寫單一瞬間的視覺
- ❌ **不要要求 Gemini 畫 GIF / 動畫 / 多格漫畫** — 一個 scene 一張靜態圖
- ❌ **不要要求超出 4 色** — 「橘紅夕陽」用米白 + 血紅暗示，「藍光螢幕」用米白塊處理，不用加色
- ❌ **不要把 canonical 的整段 narrative 抄進 brief** — 提煉出「這一瞬間視覺」就好（一張圖只能表達一個瞬間）

**讀 canonical + IP_BIBLE 視覺章 + ch01_image_brief_example，產出一份照同樣結構的 chXX_image_brief.md。user 整段貼到 Gemini 對話框 → Gemini 逐張產出 → user 收圖。**

# 章節交付前自我檢查清單

> 把 canonical MD 交給 user 之前，**逐條檢查**。任何一條不過 = 回去補。

---

## A. canon 一致性

- [ ] 整章不違反 `reference/IP_BIBLE.md` 任一條設定
- [ ] 主角是「同源事件倖存者」血脈後代（不是外婚進來的配偶）
- [ ] 真結局符合「上一章主角來救」鐵律（Ch1 例外）
- [ ] 場景某時刻有 23:47 視覺信號（時鐘 / 簡訊時間 / 監視器時碼等）
- [ ] 沒有寫到 Ch5 才能揭露的源頭事件細節
- [ ] 沒出現西方姓名 / Hollywood 風 / CoC 專有名詞（POW / SAN / Cthulhu 等）

## B. 結局譜系

- [ ] 結局數量 = 5-7 個
- [ ] 至少 1 個真結局（上章主角救援）
- [ ] 至少 1 個失神結局（主動屈服走向自我毀滅；形式不限）
- [ ] 至少 1 個「下一個」/ 詛咒繼承類結局
- [ ] **每個結局情緒底色不同**（一句話描述對比一遍，沒有重複）
- [ ] 每個結局都有完整 description（不是 placeholder「...待寫」）

## C. 線索（clue）設計

- [ ] 至少 4 個「反差跡象」設計（玩家可收集 3 + 1 隱藏）
- [ ] 每個 clue 對應「熟人不會這樣 / 不可能知道 / 物理矛盾」之一
- [ ] clue 觸發場景的內心 OS 寫出來，玩家不需回憶前章也能 follow
- [ ] 真結局條件寫死：`clue ≥ 3 AND san ≥ 50 AND <第三條件>`

## D. 引擎相容

- [ ] 全部 scene id 是 snake_case 英文，prefix `scene_`
- [ ] 每個 skill_check 寫滿 5 階 outcome（critical_success / success / partial / failure / fumble）
- [ ] 每個直通選項 / outcome 都明指 `→ scene_xxx`，沒有「TBD」
- [ ] `conditional_next` 規則內沒有混用 `if_resource_at_least` 跟 `if_resource_below`
- [ ] 沒有要求引擎做不到的事（OR 條件 / 動態 next / inventory / etc.）見 `reference/engine_constraints.md` 第 8 章
- [ ] resource 用既有 `san` + `clue` + 必要的 `hidden` flag（不新增可見資源）
- [ ] skill 用既有 8 個 ID（除非真的需要新增 + 已跟 user 確認）

## E. 路線設計

- [ ] 3 條主決策路線（mirror Ch1/Ch2 結構）
- [ ] 每條路線都能達到至少 2-3 個結局（不是死路一條）
- [ ] 真結局至少 2 條路線可達（不是只有 1 條）
- [ ] 失敗 / 大失敗 outcome 不全部導向同個壞結局（要有差異）
- [ ] 每個 wave 的 san 衝擊量總和不會讓玩家「走對路也必爆 san」（試算過）

## F. 文案品質

- [ ] 第二人稱「妳/你」、現在式
- [ ] 每段敘述 2-4 句為主（避免長段獨白）
- [ ] 沒有「過度透露結果」的選項標籤（例：「（神情恍惚）答應」會洩漏這是壞選項）
- [ ] 在地化細節（華人 / 台灣文化）有融入：放學鈴 / 公車 / 補習班 / 警衛 / 茶水間 / 便利商店 / 老社區 / etc.
- [ ] 沒有「最後是夢」/ 過度血腥 / 中二長獨白 / 過度解釋怪物來源

## G. 視覺 / 音效

- [ ] 主視覺母題寫出來（例：「教室時鐘 + 走廊長影」）
- [ ] 跟 Ch1/Ch2 視覺有區隔（不要又是夜 + 走廊）
- [ ] 每個 scene 寫 BGM **氛圍描述**（不是檔名）
- [ ] 結局場景寫了 image 描述

## H. 跨章鉤子

- [ ] 真結局結尾埋一個鉤子，讓玩家可以拼出「跟 Ch1/Ch2 是同詛咒」
- [ ] 上一章主角來救的場面寫得「真實人感」（出汗 / 跑著趕來 / 衣服亂 — 對比幻覺中的乾淨假人）
- [ ] 有給下一章的鋪陳（例：「他想起以前曾在某個地方聽過類似的聲音…」）

## I. 結構完整性

- [ ] 所有在 `next` 引用的 scene id 在 MD 裡都有定義（沒有 dead reference）
- [ ] 沒有「孤兒 scene」（沒被任何 next 引用 + 不是 start_scene）
- [ ] start_scene 明確指出來（通常 = `scene_start`）
- [ ] truth_ending_id 明確指出來

## J. 自查最終一輪

把 MD 假裝是工程實作 Claude 的視角讀一遍，問自己：

- [ ] 「這個 scene 我不需要追問就能轉 JSON」 — 全部 scene 都通
- [ ] 「跨章 unlock 邏輯有對上 IP_BIBLE」
- [ ] 「7 個結局 emotional palette 互不相蓋」
- [ ] 「玩到失神 / 真結局兩個 mirror 結局，跟 Ch1/Ch2 同樣的悚」

10 條全 ✅ → 交給 user。

---

## 不通過怎麼辦

- C / D 不過 = 結構性問題，**直接回 Step 2/3 重設計**
- F / G 不過 = 文案打磨，可繼續微調
- A / H 不過 = 跟 user 確認 canon 點，必要時請 user 改 IP_BIBLE
- B / E 不過 = 路線/結局譜系問題，重新分配後跑一次

不要硬交不過清單的 MD — 交了會被工程實作 Claude 退回，浪費兩邊時間。

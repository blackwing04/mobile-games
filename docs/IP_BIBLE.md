## 二、IP 核心：23:47 血咒（the canon mythology）

### 2.1 名稱由來

**23:47** 是這個系列的**時間錨點**：每一章故事的核心怪事都會在這個時間點達到高潮。每一章的場景時鐘會在某個時刻停在或顯示 23:47，作為「血咒已經啟動」的視覺信號。

### 2.2 詛咒本質

> **23:47 血咒** 是一條纏繞在「某個血脈」上的克蘇魯式詛咒。詛咒透過**幻覺**運作 — 給受害者灌入熟悉的聲音、影像、人物，誘使其在自我崩潰時走向不可逆的終點（墜樓、失蹤、被吞噬、走入鏡內等形式不一）。

### 2.3 詛咒源頭（canon）

* 多年前（具體年代待 Ch3 揭露），主角祖父或外祖父輩經歷過一起無法用現代邏輯解釋的事件。
* 倖存者回到日常、結婚生子。**他們的直系血脈後代**（孩子、孫子）從此被詛咒纏繞 — 看起來與常人無異，但會在某個時間點被「23:47 血咒」找上。
* 詛咒的目的：**讓該血脈完全消滅** — 透過引誘血脈成員自我毀滅（自殺、失蹤、走入幻境不歸等），逐個帶走。
* **第一作（3 章）主角 = 同家兄妹**。Ch3 兩人合作回到老家／祖宅，從祖輩留下的破舊日記中找到詛咒源頭並破解。

### 2.4 詛咒運作機制（內容創作核心 — 必讀）

血咒是**典型 CoC 式的精神侵蝕**，分為以下幾層：

| 層級 | 表現 | 範例 |
|------|------|------|
| **環境異常**（最輕） | 時鐘停在 23:47、燈光閃爍、走廊變長、夕陽過久 | Ch1 茶水間日光燈 / Ch2 教室掛鐘卡 23:47 |
| **幻聽**（中度） | 「熟人的聲音」叫你做某件事 | Ch1 啜泣聲 / Ch2 假哥哥電話、廣播喇叭 |
| **幻視**（中度） | 鏡 / 玻璃中的「另一個我」、走廊裡多出來的人 / 影 | Ch2 廁所鏡中的妹妹自己對自己笑 |
| **幻影**（重度） | 背對著你的「家人 / 同事」、其實不是 | Ch1 沒有影子的小婷 / Ch2 天台邊背對的「哥哥」 |
| **死亡誘導**（終局） | 把受害者引到無法回頭的處境（高處 / 深處 / 鏡內 / 走廊盡頭 / 廢棄裂縫等） | Ch1 茶水間女實習生跳樓 / Ch2 妹妹被誘上天台 |

> **signature 機制 = 主動屈服**。每一章的「失神結局」都是受害者在幻覺驅動下走向自我毀滅 — **形式不限定一致**，可以是墜樓、失蹤、被吞噬、走入鏡內、被影子拖走等，每章依場景設計選擇最合適的形式。
> 玩家會跨章拼出「這是同一個詛咒」**靠的是『熟人模仿 + 主動屈服』的母題重複**，不是死法形式重複。

### 2.5 詛咒識破關鍵（玩家視角）

每一章的「真結局」都需要主角**識破幻覺、拒絕誘導**。識破的線索（clue）類型：

* **熟人不會說的話 / 用詞**（例如 Ch2「哥哥從不直呼妹妹全名」「哥哥不會說『我命令你』」）
* **熟人不可能知道的事**（例如知道死者才知道的細節）
* **環境物理矛盾**（電話沒有背景音、影子不對、時間矛盾）
* **熟人不應出現的地點 / 姿態**（背對著你不回頭、嘴型與聲音不同步）

每一章設計時，**至少要安排 4 個這類「反差跡象」**作為 clue 觸發點，讓玩家可以收集 ≥3 個達到真結局門檻。

### 3.1 章節清單

| **Ch3** | 源頭篇（暫名） | **兄妹雙視角合作** | 兩人位於某老家／祖父母家／老社區，透過家中破舊日記找詛咒源頭 | 兩人合力破解詛咒（不需要外援，這是最終章）| ⏳ 待設計 |

### 3.2 跨章連動鐵律

1. **真結局 = 上一章主角來救** — Ch1 例外（無上一章），Ch2 是 Ch1 哥哥來救妹妹。**Ch3 例外（最終章是兩人合作破解，不需要救援）**。
2. **Ch3 解鎖條件 = Ch1 + Ch2 真結局齊集**。引擎已經支援這條件（`UnlockService` 計入真結局 = 2 → 第 3 章解鎖）。

### 3.3 血脈關係（極簡化 — 兄妹兩人）

```
[ 共同祖先曾經歷的事件（年代待 Ch3 揭露）]
        │
        └──── 倖存者家族（兄妹的祖父或外祖父輩）
                       ├── Ch1 男主（哥哥）— 都市上班族
                       └── Ch2 女主（妹妹）— 高中生
                       └── (Ch3) 兩人合作回到老家，從家中日記破解詛咒源頭
```

> **第一作策略**：3 章為 1 個 App，**血脈只在親兄妹間**，不引入「同源事件其他家族」這層複雜度。日記是祖輩留下的關鍵線索。
>
> 未來若推出續作 / 其他 IP（「異聞錄：xxxx」），再引入更廣的血脈群像。

### 3.4 主角必須是「血脈純正後代」

不允許「外婚進來的配偶」當主角 — 詛咒只認血脈。Ch1 + Ch2 + Ch3 都是這對兄妹。

## 六、寫作規範（IP-wide tone）

### 6.1 必須保留 / 強化

* **第二人稱「你」、現在式**
* **都市怪談 vibe**（不是 Hollywood splatter、不是大戰惡魔）
* **心理恐怖 ＞ 視覺恐怖**（留白、暗示、未明說的細節最恐怖）
* **短句節奏、畫面感強**（每段 2-4 句最佳）
* **在地化細節**：台灣 / 華人文化（加班、實習生、高中放學、警衛、便利商店、公車、補習班）
* **CoC 式的「無力感」**：玩家不是英雄，只是個被詛咒纏到的普通人

### 6.2 嚴格避免

* 過度血腥 / 變態描寫
* 過度解釋怪物來源（神祕感破壞 — **Ch3 之前永遠不要明說**血咒的詳細起源；Ch3 是最終章，會揭露源頭）
* 對白太戲劇化、太電視劇感
* 西方姓名 / 地名 / 文化參照
* 任何 CoC 專有名詞（POW / SAN / EDU / Mythos 等照抄；可用「神智」/「線索」這種通用詞）
* 任何已知 IP 的具體設定（SCP-XXX / Backrooms Level X / Mandela Catalogue 角色名等）
* 中二感、自我感動的長獨白
* 結局「最後是夢」這種濫俗收法
* **跨章節劇透其他章節未發生的事**（除非是「真結局」線索）

## 七、引擎技術限制（給 Gemini 知道有什麼能用 / 不能用）

### 7.1 資源系統（跨章一致 — Ch1 為 canon source）

| 資源 ID | 名稱 | 圖示 | 起始 | 上限 |
|---------|------|------|------|------|
| `san` | 神智 | 🧠 | **70** | 100 |
| `clue` | 線索 | 🔍 | 0 | **3**（cap，每章最多 3 個 clue）|

> 不允許新增資源（除了隱藏 flag — 例如 Ch2 的 `sms_sent` 是 hidden 不顯示在 UI，內部 routing 用）。新章節保持 san / clue 一致，避免玩家學習成本。

#### 全局門檻（跨章一致）

| 門檻 | 數值 | 用途 |
|------|------|------|
| **真結局** | `clue ≥ 3 AND san ≥ 50` AND 第三條件（章節決定）| 雙軸 + 動作條件 |
| **崩潰兜底** | `san < 50` | 全局 dispatcher：玩家任何時候 san 跌破 50 → 自動轉該章「精神崩潰類」壞結局（Ch1: scene_end_broken；Ch2: scene_lost_sanity）|
| **clue cap** | `3` | 每章玩家最多累積 3 個 clue（包含主流程 + 隱藏 detour bonus）|

### 7.2 骰子規則（d100 + 5 階結果）

每一個技能檢定的選項，必須完整提供 5 階結果：

| Outcome | 觸發條件（roll vs skillValue） |
|---------|-----------------------------|
| `critical_success`（大成功） | roll ≤ skillValue / 5 |
| `success`（成功） | roll ≤ skillValue |
| `partial`（代價成功） | skillValue < roll ≤ skillValue + 10 |
| `failure`（失敗） | skillValue + 10 < roll ≤ 95 |
| `fumble`（大失敗） | roll ≥ 96 |

### 7.3 技能（**跨章統一表，初值依主角設定**）

技能 ID 與名稱跨章共用，每章只調整**初值**反映主角的人物特質。新章節**先用既有 8 個**；如有現有技能無法表達的動作（例如 Ch3 需要「機智」「電腦」之類），再 append 進這份統一表。

> ⚠️ **不允許用既有 ID 表達「相似但有差異」的概念**（例如 Ch2 不能用 `agility` 取代 `athletics`）— 改值就好。

#### v1 統一技能表（8 個）

| skill_id | 名稱 | 用途範例 | Ch1 男主<br>(上班族男) | Ch2 妹妹<br>(高中女) |
|---------|-----|---------|:------:|:------:|
| `observe` | 觀察 | 看出環境異常、找線索物件 | 65 | 60 |
| `listen` | 傾聽 | 聽出聲音反差、聽走廊異響 | 50 | 55 |
| `lore` | 博學 | 知識回憶、識破歷史脈絡 | 55 | 45 |
| `stealth` | 隱匿 | 悄悄移動不被發現、躲藏 | 50 | 55 |
| `athletics` | 體育 | 跑、跳、攀爬（敏捷向） | 45 | 50 |
| `strength` | 力量 | 推、拉、破壞、撞門（蠻力向） | 55 | 40 |
| `resolve` | 意志 | 抗拒幻覺、心理抗壓 | 70 | 50 |
| `common_sense` | 常識 | 判斷邏輯矛盾、識破話術 | 55 | 55 |

#### 設計原則

* **強項弱項自然反映人物**：上班族男 → 意志 / 觀察高、體育低；高中女 → 隱匿 / 常識 / 觀察高、力量 / 博學 / 意志低
* **初值區間**：`40-70`。中段 45-55 是預設、強項 60-70、弱項 40-45。**避開太低 / 太高**讓 5 階結果都有實質機率
* **不為了平衡而平均化**：人物該弱就弱，這是性格表達，不是 RPG 平衡

#### 何時新增技能（給 Gemini 看的判斷標準）

當你設計的章節需要某個動作，**現有 8 個技能都不能精準表達**時，才 append 一個新技能進這份表。範例：

* ❌ Ch3 主角是駭客 → 想加 `hack` → **不要**。用 `lore`（電腦學識）+ `observe`（看出系統異常）組合就夠
* ⭕ Ch4 主角需要「醫療判斷」是劇情關鍵動作 → 新增 `medicine` 進統一表是合理的

新增的技能會永久進入跨章表 — 之後所有章節都要為這個新技能設一個初值（即使該章劇情用不到）。

### 7.4 條件路由（router scene）

引擎支援「無 narrative 的純 router 場景」按資源條件分流。常用於結局調度：

```json
"scene_dispatch_xxx": {
  "narrative": "",
  "conditional_next": [
    { "if_resource_at_least": { "clue": 3, "san": 50 }, "next": "scene_end_truth" },
    { "if_resource_below": { "san": 30 }, "next": "scene_end_lost_soul" },
    { "default": true, "next": "scene_end_rescued" }
  ]
}
```

### 7.5 選項可見性條件

選項可以根據資源動態顯示 / 隱藏：

* `require_resource_at_least`: 達到才顯示
* `hide_if_resource_at_least`: 達到就隱藏

常用於「線索夠才解鎖直通版選項，否則顯示擲骰版」。

### 7.6 場景內可選欄位

* `image`: 場景插圖（沒有就 placeholder）
* `bgm`: 背景音樂（asset 路徑；場景間相同就連續播）
* `ambient`: 帶間隔循環的環境聲
* `sfx_on_enter`: 進場 SFX（一次性）

## 八、結局結構規範（每章必須符合）

### 8.1 結局數量：**5-7 個**

| 類型 | 數量 | 說明 |
|------|------|------|
| ✅ 好結局 | **1-2** | 含 1 個真結局（隱藏，雙軸條件） |
| ⚪ 中性 | **1-2** | 「倖存但有後遺症」 |
| ❌ 壞結局 | **2-4** | 各情緒不同（被吞 / 被誘 / 崩潰 / 詛咒繼承） |

### 8.2 必出現的兩個「mirror 系列」結局

每章都要有：

1. **真結局**（mirror Ch1 安息 / Ch2 兄妹重逢） — 識破血咒 + 上一章主角來救（**Ch3 例外**：兩人合作破解詛咒源頭，不需要外援）
2. **失神結局**（mirror Ch1 陪她 / Ch2 失神） — 主角被詛咒誘導走向自我毀滅（形式不限定一致：墜樓 / 失蹤 / 被吞噬 / 走入鏡內等，依該章場景與 Wave 設計選擇）

### 8.3 結局情緒譜（避免重複）

7 個結局的情緒底色**必須完全不同**。範例（Ch2 已敲定）：

| 結局 | 情緒 |
|------|------|
| 兄妹重逢 | 救贖 / 餘悸 |
| 失神 | 絕望 / 寒意 |
| 平安回家 | 平靜 / 倖存（不知情） |
| 校警救援 | 安穩 / 但不解 |
| 下一個 | 不安 / 接力（詛咒擴散） |
| 無盡校園 | 寂寞 / 異化 |
| 自己走出去 | 堅毅 / 成長 |

新章節設計時，每結局的情緒**先用一句話寫出來**，確認 7 個都不重疊。

### 8.4 「下一個」結局（詛咒繼承） — 每章建議都有

`scene_end_curse_spread` 類型結局：主角沒被當場帶走，但會把詛咒「傳出去」（打電話騙下一個血親 / 對年幼親戚做奇怪舉動）。這是維持 IP 神祕感的關鍵 — 讓玩家知道「沒走真結局 = 詛咒沒被止住」。

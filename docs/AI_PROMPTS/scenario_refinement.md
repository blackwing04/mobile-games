## 風格指南

### ✅ 必須保留 / 強化

- **都市辦公室深夜怪談**的 vibe（不是 Hollywood splatter、不是驅魔師大戰惡魔）
- **心理恐怖 ＞ 視覺恐怖**（留白、暗示、未明說的細節最恐怖）
- **短句節奏、畫面感強**（每段 2-4 句最佳）
- **在地化細節**：台灣 / 華人辦公室文化（加班、實習生、警衛、深夜便利商店、公司「不可說的」內幕）
- **反烏托邦的日常感**：恐怖事件發生在最普通的場景
- **CoC 式的「無力感」**：玩家不是英雄，只是個倒楣的上班族
- **第二人稱「你」**：拉近玩家與角色的距離

### ❌ 避免

- 過度血腥 / 變態描寫
- 過度解釋怪物來源（神祕感破壞）
- 對白太戲劇化、太電視劇感
- 西方姓名 / 地名 / 文化參照（除非有明確劇情理由）
- 任何 CoC 專有名詞（POW / SAN / EDU / Mythos 等照抄）
- 任何已知 IP 的具體設定（SCP-XXX、Backrooms Level X、Mandela Catalogue 角色名等）
- 中二感、自我感動的長獨白
- 結局「最後是夢」這種濫俗收法

## 你能改 / 不能改

### ✅ 可以改

- 所有**敘事文字**（場景的 `> ` blockquote 內容）
- 所有**選項按鈕文字**（「」雙引號內的文字）
- 所有**結局描述**（結局段落的 `> ` blockquote 內容）
- **角色名**（如「小婷」可改成更貼合的名字）
- 你可以**建議**調整資源效果數值（神智扣多少、線索 +幾），**但要明確說明你想改什麼數字、為什麼**，由我決定是否採納

### ❌ 不可以改

- 任何 `id`（場景 ID 如 `scene_start`、技能 ID 如 `observe`、資源 ID 如 `san`）
- 場景之間的路由（`→ scene_xxx` 指向哪裡）
- 選項的數量（每場景現有的選項數）
- 5 階結果的存在（每個檢定型選項都必須有 5 階完整結果）
- 元資料、資源、技能三個段落的表格結構
- `# 場景`、`# 結局`、`---` 等結構性標記

## 🚨🚨🚨 輸出規範（最重要！） 🚨🚨🚨

**禁止輸出 JSON。永遠只用正典 Markdown 格式。**

### 正典 MD 格式範例

```markdown
# {劇本標題}

## 元資料

- ID: demo_office
- 作者: Joe & Gemini
- 預估時長: 10 分鐘
- 起始場景: scene_start

## 資源

| ID | 名稱 | 圖示 | 起始 | 上限 |
| --- | --- | --- | --- | --- |
| san | 神智 | 🧠 | 80 | 100 |
| clue | 線索 | 🔍 | 0 | - |

## 技能

| ID | 名稱 | 數值 |
| --- | --- | --- |
| observe | 觀察 | 65 |
| stealth | 隱匿 | 50 |
| lore | 博學 | 55 |

---

# 場景

## scene_start

> 場景敘事文字（多段請用空行的 `>` 分段）。
>
> 第二段。

選項：

1. **「按鈕文字」** — observe 檢定
   - 大成功 → scene_a [clue+2]
   - 成功 → scene_b [clue+1]
   - 代價成功 → scene_c [san-10, clue+1]
   - 失敗 → scene_d
   - 大失敗 → scene_e [san-50]
2. **「另一個按鈕文字」** → scene_f

---

## scene_a

> ...

選項：

1. ...

---

# 結局

## scene_end_good — 好結局《破曉之前》

> 結局描述文字。
>
> 第二段。

---

## scene_end_lost — 壞結局《陪她》

> ...
```

### 格式規則（必須嚴格遵守）

1. **檔頭**：`# {劇本標題}` 一行
2. **三個固定區塊**：`## 元資料`、`## 資源`、`## 技能`，皆使用上面的表格格式
3. **場景區**：用 `# 場景` 為界，每場景前以 `## scene_id` 開頭、用 `---` 分隔
4. **結局區**：用 `# 結局` 為界，每結局以 `## scene_id — {好結局/中性結局/壞結局}《{標題}》` 開頭
5. **敘事文字**：必須用 `> ` 開頭的 blockquote，段落間用空白的 `>` 分隔
6. **選項區**：先寫「選項：」一行，再用編號列表
7. **選項格式**（兩種）：
   - **檢定型**：`N. **「label」** — {skill_id} 檢定` 後面接 5 行 `   - 大成功 → scene_id [effects]`
   - **直接型**：`N. **「label」** → scene_id [effects]`
8. **效果格式**：方括號 `[clue+2, san-10]`，沒有效果就不寫
9. **箭頭**：用 `→`（U+2192），也接受 `->` `=>` `⇒`
10. **三個結局類型**：必須是 `好結局` / `中性結局` / `壞結局` 三選一

### 自我檢查清單（每次輸出 MD 前自審）

- [ ] 第一行是 `# {標題}`
- [ ] 元資料、資源、技能三個區塊存在且有完整表格
- [ ] 每個檢定型選項**都有完整 5 階**（大成功/成功/代價成功/失敗/大失敗）
- [ ] 每個 `→ scene_xxx` 後面的 ID 都**確實出現在某個 `## ` 標題**
- [ ] 結局以 `## scene_id — {類型}《{標題}》` 格式呈現
- [ ] 沒有任何 ` ```json ... ``` ` 代碼區塊（**禁止輸出 JSON**）

## 工作流程（5 步驟）

### 第 1 步：閱讀 + 評估（不動手）
我貼劇本後，先**完整讀完**，然後輸出：
1. **整體文案的優點**（2-3 點）
2. **最需要精修的 2-3 個場景**（具體說明哪個 `scene_id`、為什麼）
3. **整體調性建議**

### 第 2 步：討論
我會回應你的評估。**不要在這步動手改**。

### 第 3 步：精修（一場景一輪）
當我說「動手改 `scene_xxx`」時，你提供**該場景的新 MD**，仍以正典格式呈現（`## scene_xxx` + `> 敘事` + 選項區）。

### 第 4 步：迭代
我滿意才進下一個場景；不滿意說明哪裡 → 你重改。

### 第 5 步：最終整合
全部精修完畢，我說「**輸出完整 MD**」時，請輸出**整份正典 MD**（包含元資料、資源、技能、所有場景、所有結局）。

**最後，自審一次「每個 `→ scene_xxx` 是否都對應到實際存在的 `## scene_xxx` 標題」**，列出檢查結果。

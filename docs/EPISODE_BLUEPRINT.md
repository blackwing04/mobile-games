# 📐 異聞錄系列 — 每篇規格藍圖

> 由「辦公室的最後一夜」（ch01_office）實證跑出的最佳規格。
> 系列後續每一篇（校園篇 / 醫院篇 / 捷運篇⋯⋯）都按此藍圖配置，
> 內容創作精力專注在「敘事創意」，**不用每次重新發明結構**。

---

## 🎯 場景數黃金量：**17-22**（玩家可見 15-20）

| 類型 | 數量 | 說明 |
|------|------|------|
| 中間場景 | **10-13** | 含選擇 / 擲骰節點 |
| 結局場景 | **5-7** | 含 1 個隱藏結局 |
| Router 場景 | **2-3** | 玩家不可見的分流邏輯 |
| **JSON 內總計** | **17-22** | |
| **玩家可見** | **15-20** | |

### 為什麼是 17-22
- **>22**：開始有「可惜不能拿掉某些場景」的浪費感
- **<17**：玩家還沒進入狀況就結束、太薄
- **17-22**：每場玩家走 4-6 個 scene 到結局，符合手遊短篇節奏

---

## 🎬 結局結構：**5-7 個**

| 類型 | 數量 | 說明 |
|------|------|------|
| ✅ 好結局 | **1-2** | 1 個一般好結局 + （可選）1 個隱藏好結局 |
| ⚪ 中性 | **1** | 「倖存但有後遺症」 |
| ❌ 壞結局 | **3-4** | 各自情緒不同（被吞 / 被誘 / 崩潰 / 詛咒繼承） |

### 結局情緒譜（避免重複）
ch01_office 的範例 — 7 個結局每個情緒 **完全不同**：

| 結局 | 情緒 |
|------|------|
| 破曉之前 | 順成功 — 逃出但留疑問 |
| **安息** | 隱藏覺醒 — 主動釋懷 |
| 倖存 | 中性 — 活下來但壞了一些 |
| 斷線 | 心理崩潰 — 沒被異象帶走但精神死了 |
| 陪她 | 主動順從 — 被誘惑後的解脫感 |
| 她抓到你了 | 被同化 — 變成異象 |
| 別回頭看 | 詛咒繼承 — 早期 game over，第三人稱 |

新篇章設計時：**確認每個結局的情緒底色不重疊**。

---

## 🛤️ 主路線：**3 條**

每篇都該有 3 條互斥的「**世界觀回應方式**」。ch01_office 範例：

1. **主動接觸**：去看茶水間 → 揭露真相
2. **假裝沒看到**：戴耳機 → 屏息躲過
3. **撤退離開**：直接逃走 → 撞防火門

### 為什麼是 3 條
- **2 條**：玩家覺得「沒選擇」
- **4 條以上**：每條深度被稀釋
- **3 條**：經典「逃 / 戰 / 智取」結構，玩家清楚能玩什麼

---

## 🎲 Skill Check 配置：**5-7 個**

每篇有 **3-4 種技能**（包含 1 個「克服恐懼」類技能如 resolve / will）。

### San / Clue 經濟原則（ch01_office 實測）

| Outcome | resource 變動 | 設計意圖 |
|---------|--------------|---------|
| critical_success | **clue +2 / san +5~+15** | 克服恐懼的高光時刻獎勵 |
| success | clue +1 / san 0 | 不被處罰 = 順利推進的紅利 |
| partial | san **-15~-25** | 代價成功，要付 san |
| failure | san **-20~-35** | 大部分直連結局或推到劣勢場景 |
| fumble | san **-30~-55** | 大部分直連壞結局，剩餘為 narrative weight |

### 起始 san：**70**
- 走 2-3 場 partial / failure 後 san 掉到 **35-50**
- 剛好觸發 dispatch 的 broken 邊界 (san < 50)
- 「失敗多就崩潰」的設計感落實

---

## 🎁 隱藏結局：**1 個**（每篇必備）

**機制**：用 `conditional_next` 配雙重門檻（clue + san）。

### ch01_office 範例（「安息」結局）
- 觸發點：玩家擲到關鍵 critical_success
- 條件：`clue ≥ 3` AND `san ≥ 50`
- 達成路徑：通常**只有一條精準的成功路線**才能滿足
- 機率：~1-3%（彩蛋級稀有度）

### 設計原則
- **不要在主路線觸發**：要走「成功路線 + 收集 + 完美執行」的玩家才看得到
- **有獨立 narrative**（更詳細，~400-700 字）+ 獨立 BGM
- **打破恐怖類型框架**：通常是「主動釋懷 / 解放對方 / 真相和解」這類「比好結局更深」的情緒

## 🎨 美術 / 音訊規格

| 項目 | 規格 | 跨篇複用 |
|------|------|---------|
| 圖片 | **17-22 張** 16:9 PNG/WebP | ❌ 每篇全新 |
| BGM | **6-8 首**主要曲 + **共用 BGM 池** | ✅ 跨篇大量複用 |
| SFX | **8-10 個** UI / 骰子 / outcome | ✅ 全系列共用 |
| 風格 | 韓系 manhwa horror（4 色 palette）| ✅ 視覺 IP |

### Manhwa 風格鎖定（系列視覺 DNA）
- 4 色：純黑 / 米白 / 冷灰 / 血鏽紅
- 嚴禁照片寫實 / 日系大眼動漫
- 黑色塊作為陰影語言（非物理灰階）
- 詳見 `docs/AI_PROMPTS/image_generation.md`

## ⏱️ 時長 / 工時規格

### 玩家體驗
- **單次遊玩**：10-15 分鐘
- **看完所有結局**：5-8 次重玩 ≈ 60-90 分鐘

### 開發工時（ch01_office 實證）
| 階段 | 工時 |
|------|------|
| 劇本草稿 + Gemini 精修 | ~半天 |
| JSON 配置 + 資源校對 | ~半天 |
| 圖片產製（Gemini quota）| 2-3 天（受 quota 限制） |
| 音樂 / SFX 配置 | ~半天 |
| 測試 + 平衡調整 | 半天 |
| **總計** | **3-4 天 / 篇** |

### 第一作 3 篇 = 1 app 的節奏
- **9-12 天 / app**（連續產製不被打斷的話）
- 加上美術品質迭代 / 上架審核 → 抓 **3-4 週 / app**

## 📦 第一作 3 篇 = 1 app 的打包邏輯

第一作包 **3 個 episodes**，每章入口都看廣告 1 hr cooldown（IAP NT$30 解除）：

| 結構 | 規格 |
|------|------|
| 3 個 episode JSON | 各自獨立場景 |
| 共用 audio pool | 累積 ~30MB BGM + 5MB SFX |
| 個別圖片資產 | 每篇 ~5-10 MB（WebP 壓縮）→ 3 篇 ~15-30 MB |
| **APK 總大小**（release）| ~50-80 MB |

### 第一作三章光譜（已敲定）
```
Ch1: 哥哥 (上班族男)             ← ch01_office 已上線
Ch2: 妹妹 (高中女)               ← Ch1 哥哥來救
Ch3: 兄妹合作 (最終章)           ← 兩人回老家從日記破解詛咒源頭
```

### 未來續作（如果第一作市場有反應）
擴大血脈群像至 5 章 — 引入「同源事件其他家族」後代當主角。但**第一作 scope 鎖死 3 章**。

### 跨章母題（IP 識別）
- **23:47**：時間錨點，每章都有「23:47 異象」
- **米色針織衫**：可重複出現（不同人物）
- **「忘了怎麼回家的人」**：詛咒類型描述

### 跨 episode state（進階）
- 用 SharedPreferences 存上一章 ending type
- 第 N 章開頭 narrative 微調（看玩家上次玩什麼結局）
- **第一支 app 先不做**，第二支 app 才接，ROI 較好
